\chapter{RESEARCH METHODOLOGY AND SYSTEM DESIGN}
\label{chap:methodology}

This chapter presents the methodology and system design of the proposed
Vision-Language-Action (VLA) framework for robot manipulation. The chapter focuses on
three priorities of the current project stage: (1) building an integrated
Vision-Language-Action pipeline, (2) satisfying practical design constraints for real
robot deployment, and (3) evaluating performance on representative manipulation tasks.


%─────────────────────────────────────────────────────────────────────────────
\section{METHODOLOGY OVERVIEW}
%─────────────────────────────────────────────────────────────────────────────

The research workflow is organized into five stages:

\begin{enumerate}[label=\arabic*)]
    \item \textbf{VLA System Development}: design an end-to-end architecture that
    receives visual observations and natural-language instructions, then produces
    executable robot actions.

    \item \textbf{Module Integration}: integrate three cooperating modules ---
    a VLM core, a Vision Expert, and an Action Expert --- into one synchronized
    inference pipeline.

    \item \textbf{Instruction Following}: train and configure the system so the robot
    can follow natural-language user requests reliably.

    \item \textbf{Generalization Optimization}: improve robustness to unseen objects,
    task compositions, and environment variations.

    \item \textbf{Manipulation Evaluation}: benchmark performance on core robot
    manipulation tasks under controlled experimental settings.
\end{enumerate}


%─────────────────────────────────────────────────────────────────────────────
\section{PROBLEM-DRIVEN DESIGN REQUIREMENTS}
%─────────────────────────────────────────────────────────────────────────────

The system design is directly derived from the identified problem and motivation:
classical robot systems are task-specific, inflexible, weak in unseen-task
generalization, and limited in natural-language understanding. To address these
limitations, the proposed VLA design follows five constraints.

\subsection{Computation and Memory Constraint}

Large multimodal backbones and action generators require significant memory and
compute budget. The implementation must operate within available GPU memory while
preserving action quality. This requires compact model configuration, mixed precision,
and efficient batching.

\subsection{Latency Constraint}

Robot control requires low-latency generation. The inference path from
image-plus-text input to executable action output must remain real-time, so each
module is designed for fast forward pass and minimal inter-module overhead.

\subsection{Action Representation Constraint}

Robot actions can be represented in discrete, continuous, or hybrid forms.
The Action Expert must balance expressiveness and stability: discrete outputs improve
parsing reliability, while continuous outputs improve motion fidelity.

\subsection{Data Constraint}

Robot demonstration data is limited and expensive to collect. The training strategy
must maximize sample efficiency through data curation, augmentation, and transfer from
pretrained visual-language knowledge.

\subsection{Integration Constraint}

The final system must coordinate perception, language grounding, and action generation
without module mismatch. Interface contracts between modules are explicitly defined to
avoid semantic drift and unstable action outputs.


%─────────────────────────────────────────────────────────────────────────────
\section{VISION-LANGUAGE-ACTION SYSTEM ARCHITECTURE}
%─────────────────────────────────────────────────────────────────────────────

\subsection{Input and Output Definition}

At each control cycle, the system receives:
\begin{itemize}
    \item an RGB observation $I_t$, and
    \item a natural-language instruction $\mathcal{U}$ from the user.
\end{itemize}

The system outputs a structured action command that can be executed by the robot arm
controller, plus an optional natural-language confirmation message for the operator.

\subsection{VLM Core}

The VLM module performs multimodal understanding and instruction grounding. It
extracts intent from language, associates intent with scene context, and produces a
high-level task representation suitable for manipulation planning.

\subsection{Vision Expert}

The Vision Expert provides task-relevant visual features (object cues, target
relations, and workspace context) that support robust action planning. It is designed
to improve perception reliability under object and scene variation.

\subsection{Action Expert}

The Action Expert converts grounded task representations into executable robot
manipulation commands. The module supports structured output formatting for robust
execution and can be configured for discrete, continuous, or hybrid action spaces
depending on controller requirements.

\subsection{Module Coordination}

The three modules are connected through explicit intermediate representations:
\begin{enumerate}[label=\alph*)]
    \item \textbf{Language-grounded task state} from VLM,
    \item \textbf{Task-conditioned visual features} from Vision Expert,
    \item \textbf{Executable action sequence} from Action Expert.
\end{enumerate}

This separation improves maintainability and enables targeted optimization of each
module while keeping end-to-end behavior coherent.


%─────────────────────────────────────────────────────────────────────────────
\section{IMPLEMENTATION STRATEGY}
%─────────────────────────────────────────────────────────────────────────────

\subsection{Training and Tuning Strategy}

The system is trained and tuned in stages:
\begin{enumerate}[label=\arabic*)]
    \item Initialize the VLM-based instruction-following backbone.
    \item Train or adapt the Vision Expert for manipulation-relevant perception.
    \item Train the Action Expert to map integrated features to executable commands.
    \item Perform end-to-end tuning to reduce cross-module mismatch.
\end{enumerate}

\subsection{Latency and Memory Optimization}

To satisfy real-time robot-control requirements, the implementation applies practical
optimization techniques, including mixed precision inference, efficient token/image
preprocessing, and lightweight module interfaces.

\subsection{Data Utilization}

Given limited robot demonstrations, the project emphasizes data quality over raw
quantity. The dataset pipeline prioritizes task diversity, instruction variety,
and balanced coverage of manipulation scenarios.


%─────────────────────────────────────────────────────────────────────────────
\section{EVALUATION PROTOCOL FOR MANIPULATION TASKS}
%─────────────────────────────────────────────────────────────────────────────

\subsection{Evaluation Objectives}

Evaluation is designed to measure whether the system satisfies the project goals:
\begin{itemize}
    \item follows natural-language instructions,
    \item generalizes to unseen tasks,
    \item maintains stable manipulation output,
    \item satisfies real-time execution constraints.
\end{itemize}

\subsection{Task Categories}

The benchmark includes representative robot manipulation tasks such as:
\begin{enumerate}[label=\arabic*)]
    \item pick-and-place,
    \item stacking,
    \item drawer or container interaction,
    \item multi-step object sequencing.
\end{enumerate}

\subsection{Evaluation Metrics}

The following metrics are used:
\begin{itemize}
    \item \textbf{Instruction-following success rate}: whether generated actions satisfy
    the user command.
    \item \textbf{Generalization score}: performance on unseen tasks relative to seen
    tasks.
    \item \textbf{Action validity}: percentage of outputs that are executable by the
    robot controller.
    \item \textbf{Latency}: end-to-end action generation time per command cycle.
\end{itemize}

\section{CHAPTER SUMMARY}
%─────────────────────────────────────────────────────────────────────────────

This chapter defined a VLA-centered system design aligned with the current project
scope. The proposed architecture integrates a VLM, a Vision Expert, and an Action
Expert to enable natural-language robot manipulation. The design explicitly addresses
compute, latency, representation, data, and integration constraints, and establishes
a task-based evaluation protocol for measuring instruction following and
unseen-task generalization.
